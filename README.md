# IT 工单 Agent

一个用 Python 和 LangGraph 开发的 IT 工单项目。用户描述问题后，系统会补问缺失信息、查阅处理规程，再生成处理计划；需要审批的操作会暂停，审批通过后继续执行。遇到故障时，通过 ReAct 调用只读工具查询日志和排障文档，给出带证据来源的诊断建议。

后端使用 FastAPI，附带面向申请人的服务门户及独立的审批处理入口。工单状态和操作记录保存在 SQLite 中，账号身份、权限检查、审批和防止重复执行的逻辑由后端处理。

这是个人开发项目，日志和下游业务使用模拟数据。可以在本地走通处理流程，但不会修改真实账号或开通权限。

## 本地运行

需要 Python 3.11 或以上版本。以下命令在项目根目录的 PowerShell 中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python -m app.auth init
python -m app.workbench --no-browser
```

启动后打开 `http://127.0.0.1:8080`，使用账号、密码登录。启动器会为缺少密码的本地账号生成独立初始密码，写入 `data/auth.accounts.txt`；重复启动不会覆盖已有密码。该文件仅供本机查看，不会提交到 Git。

| 账号 | 身份 | 门户权限 |
|---|---|---|
| `alice`、`bob` | 员工 | 提交、补充、撤销和查看自己的工单 |
| `manager` | 经理 | 自己的工单，以及本部门的审批和处理 |
| `admin` | 管理员 | 自己的工单，以及跨部门的审批和处理 |

账号、角色和部门由服务端校验，页面不能自行选择身份，申请人不能审批自己的申请。网页登录使用会话 Cookie；`data/auth.keys.json` 仅供 CLI 和程序调用使用。

工作台会同时启动一个本地 HTTP 模拟服务（端口 `8091`），用于演示故障登记。按 `Ctrl+C` 关闭两个服务。

直接启动 `python -m app.api` 时，先执行 `python -m app.auth init-passwords`，为已有身份配置补充网页登录密码。

完成环境和身份初始化后，也可以运行命令行示例：

```powershell
python run_demo.py
```

## 用户门户与本地登录

- “我的工单”只展示当前申请人的工单，突出处理进度、待补充信息、申请确认和下一步操作。
- 部门经理审批本部门的权限申请；支持人员按配置的支持组跨部门核查故障。管理员可处理所有组，申请人不能审批或处理自己的申请。
- 用户门户、旧 `/tickets/...` 接口及常规 CLI 均按身份筛选字段。申请人只获得业务信息，内部状态、诊断轨迹和检索原文仅供有对应支持组权限的处理人员查看。
- 故障排查未形成可用结论时显示“待支持核查”。Agent 完成登记或生成报告，不等于外部故障已解决；只有明确核实后才显示已解决。
- 认证文件使用 PBKDF2-SHA256 加盐密码哈希；`auth.accounts.txt` 是本机初始密码交付文件，服务端不会读取它进行认证。
- 服务端会话最长 8 小时，刷新页面可恢复，退出后会话撤销。Cookie 设置 HttpOnly 和 SameSite=Strict，HTTPS 下设置 Secure；Cookie 认证写操作校验来源与 CSRF，登录尝试有频率限制。

身份配置即时重新校验，停用后拒绝后续请求；角色、部门、支持组或密码变化使旧浏览器会话失效。审批默认 24 小时有效，并在审批及实际执行前复核申请人和审批人的当前资格；已失效及缺少身份绑定的历史未决审批交人工核查。请勿上传 `.env`、认证文件、初始密码文件、会话库或本地业务数据库；对应路径已加入 `.gitignore`。

支持组由服务端 `auth.json` 的 `support_groups` 配置：`network` 对应 VPN、`applications` 对应 ERP、`data` 对应报表数据库、`service_desk` 对应本人账号及未定系统。支持角色为 `support`，经理需显式加入组才能办理故障。默认演示 `manager` 兼任四个组；生产使用时应按职责分配。处理人停用或失去组权限后，巡检释放认领并更新版本，其他有权人员可继续接单。配置格式见 [工作台说明](docs/WORKBENCH.md)。

## 故障的持续跟进与人工处理

- 故障登记或调查结束后，工单保留在支持队列。支持人员提交处理结果后，进入待申请人验证；用户实际确认恢复才标为已解决，验证失败继续在原工单跟进。没有诊断报告也能认领和处理。
- “ERP 报错 503，怎么处理？”按真实报障受理。缺少必要信息时继续澄清；敏感操作仍需本人确认及相应审批。
- 调查缺少用户能提供的信息时，会询问发生时间、具体表现、复现步骤或此前使用情况。补充后沿用原事件继续调查，保留历史证据，不重复登记或授权；默认最多调查 3 轮、自动追问 2 次，超过预算交给支持人员跟进。
- 支持入口提供“待认领”“我负责的”“已超期”队列，以及认领、转派和请求补充操作。申请人与处理人分别记录；只有当前处理人能提交核查结果或结案，管理员可填写原因后接管。
- 按严重程度设置处理期限，等待用户补充时暂停计时；超期提醒通过站内队列呈现。下游写入结果不明时，必须持凭证人工核查结案，普通反馈不能绕过该限制。
- 启动时将尚未确认解决的历史关闭故障恢复为支持待办，保留原登记回执和报告，不重放业务动作。
- 首次登记同时传递原始描述、澄清后的有效描述和各轮用户补充。登记前保存与执行计划绑定的信息快照，重试与恢复沿用同一内容，旧登记回执保持兼容。
- 后台有独立巡检，默认排队时限 120 秒、单次运行时限 90 秒；异常、超时或工作线程中断后转入可认领的支持待办。当前处理人可发起重新排查，每轮最多运行 3 次（首次加 2 次重试），达到上限转人工处理。迟到任务不能覆盖人工结果，未知附件写入仍需核查。
- 调查附件按工单和报告版本保存，多轮报告不会互相覆盖。旧附件在事务中迁移为版本 1，原内容和回执保留；人工反馈、结案的 HTTP/CLI 请求需要读取时的 `case_revision`，旧页面不能提交对新版报告的核查。
- 待补充信息默认 48 小时，超时回到人工待办；待用户验证默认 72 小时，超时归档为未确认解决。申请人可报告自行恢复或撤回后续处理，处理人可归档无人回应的工单。结束后默认 7 天内可在原工单反馈复发，保留原事件、证据和各次处理记录。

状态、接口和演示步骤见 [工作台说明](docs/WORKBENCH.md)。

## 身份与业务账号关联

登录身份与业务账号分别管理。后端读取本机 `data/account_bindings.json`，按申请人及资源选择业务账号；默认 bob 对应 ERP 的 `erp.bob`、VPN 的 `vpn.bob`。确认页显示实际目标，审批冻结目标快照，执行前重新核验，关联变化不会沿用旧授权。客户端和模型不能指定另一人的账号，支持组也只能看到当前工单所需的关联信息。

VPN、ERP 的演示日志覆盖四个演示身份，包含独立会话。未绑定账号、日志源未接入、无读取权限、账号未覆盖或无记录会明确交给支持人员，用户可以继续跟进原工单；模型不会借用其他用户的日志填补缺口。报表数据库仍由支持组人工处理。日志与业务动作仍为模拟数据，真实系统接入需提供对应只读适配器。

初始化演示身份或启动工作台会建立缺少的演示关联文件，并保留已有配置；自定义身份须明确配置。示例见 `data/diagnostics/account_bindings.example.json`，完整边界及迁移说明见 [工作台说明](docs/WORKBENCH.md)。真实关联文件已加入忽略列表，请勿将其提交到公共仓库。

## 重复提交与刷新恢复

页面按账号在当前标签页保留未确认的提交，刷新后可继续确认原申请，退出登录会清除缓存。后端按同一申请人、部门及相同标题、描述、影响程度复用未结束工单，不依赖浏览器保留幂等键；并发或换编号重试也不会重复登记和执行。新建返回 201，复用原单返回 200，并在页面说明已打开原工单。

已撤销、已拒绝、已归档、已解决或审批失效后可重新申请。自动完成的重置密码、授权默认再保护 600 秒，防止响应丢失后重复操作；可通过 `AGENT_SUBMISSION_COMPLETED_WINDOW_SECONDS` 调整。同一提交编号始终绑定原申请，改内容会拒绝。业务指纹、提交编号绑定与初始工作流占位在同一 SQLite 事务中保存，模型和下游调用在事务外执行；未知操作由支持人员核查，重复提交不会自动重放。

## 默认怎么运行

- 默认用离线规则代替模型响应，不需要 API Key，方便先把流程跑起来。
- 诊断采用 ReAct 流程，工具只读取信息，并限制调用次数和耗时。使用真实模型决策需要配置下面的 DeepSeek。
- 排障文档检索配置为 BM25 + BGE 融合召回；未下载 BGE 时，使用词法检索。
- 命令行示例在本地模拟执行；网页工作台通过上述 HTTP 模拟服务登记故障。

## 可选配置

### DeepSeek

在 `.env` 中填写 `DEEPSEEK_API_KEY`，将 `AGENT_LLM_MODE` 改为 `deepseek`。`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 按所用 API 服务填写。修改后重启服务。

### BGE 向量检索

```powershell
pip install modelscope
python scripts/download_embedding.py
```

下载后重启服务即可使用。模型保存在 `data/models/`，不会提交到 Git。

### Cross-Encoder 重排

需要对召回结果进一步排序时，下载重排模型并重启服务：

```powershell
python scripts/download_reranker.py
```

没有本地重排模型时，系统保留融合召回的排序结果，并记录未执行重排的原因。

## 验证

在安装依赖的项目环境中运行完整回归测试：

```powershell
python -m unittest discover -s tests -v
```

共 324 项测试，使用临时数据、离线模型或模拟响应，不调用真实模型 API。`scripts/check_portal_dom.cjs` 提供 18 项前端 DOM 交互检查，覆盖登录、会话恢复、角色边界、认领、补充信息、受限重试、用户验证、原单重开及带版本的人工处理，需要单独安装 jsdom、postcss 开发依赖；工作台运行本身不需要 Node。`scripts/check_workbench_browser.cjs` 用于隔离数据环境中的浏览器验收，需要 Playwright，历史报告不能替代当前版本的浏览器验收。
