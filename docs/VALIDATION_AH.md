# A–H 整体升级与验证记录（2026-09-29）

> 历史实验记录：本文描述 A–H 升级当时的配置与结果，不是当前运行指南。后续 v3 已将诊断检索默认切换为适用范围优先的 BGE 向量检索，并接入独立 HTTP 演示服务和工作台。当前实现见 [README](../README.md) 和 [工作台说明](WORKBENCH.md)；下列实验数据保留原始口径。

本次升级将 RAG 从通用动作分类的必经向量检索，调整为版本化排障知识服务；同时调整故障登记、后台调查、证据交付与反馈的生命周期。
范围是个人求职项目的受控 IT 服务场景，身份与下游仍为模拟，不以企业生产收益作为已证实结论。

## 新知识服务的对照

证据：[knowledge-value-release-20260929.json](../data/evaluations/knowledge-value-release-20260929.json)。
6 个自编开发案例，每组重复两次。固定日志与生成提示词；仅改变提供的知识。生成模型看不到 expected_runbook、required_topics 等评分标签。
试验期间记录代码和知识哈希，code_unchanged=true。

| 方案 | 暂定语义通过 | 生成 token | 评审 token |
|---|---:|---:|---:|
| 无知识 | 5/12 | 10,057 | 16,102 |
| 历史关键词规程 | 8/12 | 13,529 | 19,757 |
| 新版 BM25 | 12/12 | 18,718 | 24,529 |
| 新版 BGE + BM25/RRF | 12/12 | 18,403 | 24,311 |
| 新版全部资源文档 | 12/12 | 33,135 | 39,130 |

三种新知识提供方式在本组试验中得分相同。BM25 相比全量资源文档减少约 **43.5% 生成 token**，且不需额外加载 embedding 模型，因此该轮实验后当时选择 BM25 为默认方案；后续 v3 的选型与结果见 README。
混合检索少量 token 差异可能来自生成波动；没有证据证明其准确率更高。无知识和旧规程更便宜，但不能总是提供模拟内部约定要求的交接信息。

评分覆盖证据支持、适用规程、交接建议及不确定性，另检查引用原文和完成修复声明。
这不是纯故障分类准确率：知道可能是 DNS 问题，却给错部署的交接要求，也可能无法完成任务。

限制：语义评审由另一次同模型调用完成，仍存在评审偏差；human_review=null。6 个案例的重复运行不是 12 个独立故障；案例和规程由开发者编写，不是盲测企业数据。不能据此宣称“企业准确率 100%”或已经减少实际人工处理时间。

较早的 pilot 和 repeat 记录均保留。首轮出现格式失败和引用 ID 被模型加后缀的失败，后续收紧了生成约束并补全用量记录。不同轮次不拼接成更好的分数。

## 端到端链路

最终证据：[ah-http-scoped-reviewed-20260929.json](../data/evaluations/ah-http-scoped-reviewed-20260929.json)，基于保留的 [原始 HTTP 输出](../data/evaluations/ah-http-scoped-final-20260929.json) 追加交接主题检查，不重新生成答案。

7 个案例通过接口、状态、身份范围、规程选择、引用完整性、幂等响应和附件交付检查：3 个已有 VPN/ERP/分支案例，4 个新的部署条件案例。
新增四个案例的实际 next_check 分别包含：

- cloud-proxy ERP：平台连接代理组、租约分配指标。
- classic-direct ERP：应用运维组、连接借还计数。
- managed-terminal VPN：终端策略组、策略修订号。
- self-managed VPN：网络支持组、域名后缀列表。

第一轮新增场景的完整链路仅 4/7 通过，记录 [ah-http-scoped-20260929.json](../data/evaluations/ah-http-scoped-20260929.json) 保留：
一例上游澄清格式失败安全停止，两例查询漏掉部署条件而选到通用规程。
修正后，检索适配器从已读日志前缀绑定环境，过滤其他部署的规程；生成的查询不能覆盖这个范围。模型仍需判断其余故障条件，而不是程序硬编码故障答案。

**7/7 不代表所有自然语言结论完全正确。** 编码助手复核发现 scope-kb-e05 摘要仍有“而非数据库本身慢”的过度排除措辞；健康探针不能排除所有数据库因素。
该意见保存在 semantic_review 中，报告仍标记 verified=false，并要求人工验证。接口成功、引用真实和语义完全正确是不同指标。

## 回归与失败处理

最终全量日志：[ah-final-200-regression-20260929.log](../data/evaluations/ah-final-200-regression-20260929.log)。
最终结果：**200 项测试全部通过**，用时 123.716 秒。
覆盖既有身份、审批、确认、语义理解、执行幂等和恢复测试，并新增知识生命周期、部署范围、反馈与异步受理测试。

关键断言包括：

- 模型被阻塞时，真实 TCP HTTP 请求仍能先收到事件登记结果；解除阻塞后附件完成。
- 崩溃发生于附件写入之后：重启复用完成账本；写入结果未知：不自动再发一次。
- 调查恢复不重置预算、截止时间，也不混用新日志；临时源文件消失仍可使用已保存快照。
- 反馈不能自审、不能由员工伪造处理人；重复版本幂等，冲突和跳版本被拒绝。
- 已执行的旧版快照不自动进入新版后台阶段；旧版登记前的调查中断要求人工核查，不擅自重放。

SQLite、预置身份和模拟适配器仍是明确的 Demo 取舍。真实业务上的处理时长、采纳率和减少补料次数，需要后续人工使用反馈；当前没有制造这些收益数字。
